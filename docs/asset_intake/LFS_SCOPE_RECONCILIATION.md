## Claim Boundary

The current branch is not zero-LFS. The correct claim is narrower:

- release-required app assets are governed by `check_release_required_assets.ps1`;
- release-required paths are blocked from Git LFS by `check_lfs_release_scope.ps1`;
- broad normalized LFS payloads are deferred curated-library inventory;
- deferred library assets are exported only when a project explicitly selects them and the export path has attribution and hydration evidence;
- deferred library inventory is not proof of final art direction, complete content, or a zero-LFS repository.

## Completion Rule

Broader asset-complete or final-art claims require one of these outcomes for each deferred library root:

1. Hydrate and verify the selected payloads on the target release commit.
2. Reclassify unselected payloads as non-release library inventory with bundle/source attribution.
3. Remove or untrack payloads that cannot be attributed, hydrated, or selected.

No release document should cite a raw `git lfs ls-files` count without also linking this reconciliation evidence.
